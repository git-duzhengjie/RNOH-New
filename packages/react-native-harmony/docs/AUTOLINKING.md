# RNOH-New Autolinking 自动链接机制

RNOH-New 提供与 React Native 类似的 autolinking 机制：在构建 HarmonyOS 应用前，
通过扫描 `node_modules` 自动识别支持鸿蒙的第三方 npm 包，并生成 C++ / ETS 两端的
包注册表与 CMake 链接配置，无需手动修改工程文件。

## 快速开始

在 `packages/react-native-harmony` 目录下执行：

```bash
# 默认扫描 ../node_modules
node scripts/generate-autolinking.js

# 指定 node_modules 路径
node scripts/generate-autolinking.js --nodeModules=../node_modules

# 或使用 package.json 脚本
npm run generate-autolinking
```

执行后会自动生成以下文件：

```text
src/main/cpp/RNHAutolinking/PackageProvider.h
src/main/cpp/RNHAutolinking/PackageProvider.cpp
src/main/cpp/RNHAutolinking/autolinking.cmake
src/main/ets/Autolinking/RNHPackageProvider.ets
```

> ⚠️ 这些文件顶部均包含 `Generated by @rnoh-new/react-native-harmony autolinking. DO NOT edit manually.`，
> 请勿手动修改，否则下次执行脚本时会被覆盖。

## 第三方 npm 包配置

第三方 npm 包可以通过以下两种方式之一声明自己支持 RNOH-New autolinking：

### 方式一：在 `package.json` 中声明 `react-native-harmony` 字段（推荐）

```json
{
  "name": "@my-org/react-native-awesome-module",
  "version": "1.2.3",
  "react-native-harmony": {
    "harmonyPath": "harmony",
    "cppPackageClassName": "AwesomeModulePackage",
    "cppLibraryName": "awesome_module_package",
    "cppHeaderPath": "harmony/src/main/cpp/AwesomeModulePackage.h",
    "etsPackageClassName": "AwesomeModulePackage",
    "etsImportPath": "harmony/src/main/ets/AwesomeModulePackage"
  }
}
```

### 方式二：在包根目录放置 `harmony/oh-package.json5`

如果 `package.json` 中没有 `react-native-harmony` 字段，但存在 `harmony/oh-package.json5`
文件，也会被视为可 autolink 的包。此时将使用默认命名规则推断类名。

---

## 配置字段说明

| 字段 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `harmonyPath` | 否 | `harmony` | 鸿蒙模块相对于 npm 包根目录的路径 |
| `name` | 否 | `oh-package.json5` 中的 `name` 或 npm 包名 | HarmonyOS 模块名 |
| `version` | 否 | `oh-package.json5` 中的 `version` 或 npm 版本 | 模块版本 |
| `cppPackageClassName` | 否 | `<PascalCase>Package` | C++ Package 类名 |
| `cppLibraryName` | 否 | `<PascalCase>Package` | CMake 库名，用于 `target_link_libraries` |
| `cppHeaderPath` | 否 | `<harmonyPath>/src/main/cpp/<cppPackageClassName>.h` | C++ 头文件相对路径 |
| `etsPackageClassName` | 否 | 同 `cppPackageClassName` | ETS Package 类名 |
| `etsImportPath` | 否 | `<harmonyPath>/src/main/ets/<etsPackageClassName>` | ETS 导入路径 |

## 扫描规则

脚本会遍历 `node_modules` 顶层目录（包括 scoped packages，如 `@rnoh-new/xxx`），
对每个包判断以下任一条件：

1. `package.json` 中包含非空的 `react-native-harmony` 字段；或
2. 包根目录下存在 `harmony/oh-package.json5` 文件。

满足条件后，脚本读取并解析元数据，生成统一的注册表代码。

## 生成文件

### `src/main/cpp/RNHAutolinking/PackageProvider.h`

声明 `createAutolinkedPackages` 函数和 `autolink_libraries` CMake 宏，
并包含所有扫描到的 C++ Package 头文件。

### `src/main/cpp/RNHAutolinking/PackageProvider.cpp`

实现 `createAutolinkedPackages`，实例化每个扫描到的 C++ Package 并加入返回列表。

### `src/main/cpp/RNHAutolinking/autolinking.cmake`

包含每个包的 `add_subdirectory` 调用，使其 CMake 子工程被自动纳入构建。

### `src/main/ets/Autolinking/RNHPackageProvider.ets`

导出 `createAutolinkedPackages` 函数，实例化每个扫描到的 ETS Package 并返回数组。

---

## CMake 集成

在根 `src/main/cpp/CMakeLists.txt` 中加入：

```cmake
# 引入 autolink 子目录
include(${CMAKE_CURRENT_SOURCE_DIR}/RNHAutolinking/autolinking.cmake)

# 在你的主 target 后链接 autolink 库
autolink_libraries(your_main_target)
```

---

## ETS 集成

在应用入口或合适的初始化位置调用：

```ets
import { createAutolinkedPackages } from './Autolinking/RNHPackageProvider';

const autolinkedPackages = createAutolinkedPackages(packageContext);
```

## 常见问题

### Q: 为什么执行后显示 `Found 0 autolinkable package(s)`？

A: 可能原因：
- `node_modules` 路径错误；
- 第三方包未声明 `react-native-harmony` 字段；
- 第三方包缺少 `harmony/oh-package.json5`。

### Q: 可以同时支持两种方式吗？

A: 可以，但优先使用 `react-native-harmony` 字段中的配置；如果未配置再使用
`oh-package.json5` 和默认规则推断。

### Q: 生成的文件需要提交到 Git 吗？

A: 建议不提交。可以在 CI 构建流程或 `prepare` 脚本中执行 `generate-autolinking`。

### Q: 是否支持递归扫描子依赖？

A: 当前版本仅扫描 `node_modules` 顶层目录。后续版本可能支持递归扫描依赖树。
