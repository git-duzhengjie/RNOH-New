# RNOH-New 性能基准测试文档

> 本文档描述 RNOH-New 项目的性能测试方法、指标目标与优化记录。

---

## 1. 性能指标目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 列表滚动 FPS | ≥ 58 FPS | 1080p 分辨率下，1000 条文本列表匀速滚动 |
| 页面切换 FPS | ≥ 55 FPS | 页面 push/pop 过渡动画期间 |
| 动画 FPS | ≥ 58 FPS | 60 帧/秒的属性动画（透明度、位移） |
| 冷启动时间 | < 500 ms | 从进程启动到首屏可交互（TTI） |
| 热启动时间 | < 100 ms | 应用从后台切回前台 |
| JS Bundle 加载 | < 200 ms | 1MB bundle 解析与执行 |
| 初始内存占用 | < 80 MB | 启动后静止 5 秒的 RSS |
| 列表峰值内存 | < 150 MB | 滚动 1000 条复杂列表 30 秒峰值 |
| 内存泄漏 | < 1 MB/分钟 | 连续页面切换 10 分钟，内存增长 |
| 首屏渲染耗时 | < 300 ms | 从 JS 执行到首帧渲染完成 |
| 组件挂载耗时 | < 1 ms/个 | 简单 View 组件平均挂载时间 |

## 2. 测试场景列表

### 2.1 列表滚动
- **场景**：FlatList/ScrollView 渲染 1000 条文本 + 图片列表
- **操作**：匀速向下滚动 30 秒，再向上滚动 30 秒
- **测量**：平均 FPS、掉帧数、Jank 数、内存峰值

### 2.2 页面切换
- **场景**：导航栈中 push/pop 页面，每页含 50 个组件
- **操作**：连续切换 50 次
- **测量**：切换期间 FPS、页面创建耗时、内存增长

### 2.3 动画性能
- **场景**：同时运行 10 个动画（透明度、位移、缩放、旋转）
- **操作**：循环播放 60 秒
- **测量**：平均 FPS、动画丢帧率、CPU 占用

### 2.4 启动耗时
- **场景**：冷启动应用到首屏可交互
- **操作**：连续启动 10 次取平均值
- **测量**：T0→TI（JS 引擎初始化）、TI→TTI（首屏可交互）、T0→TTI（总启动）

### 2.5 内存稳定性
- **场景**：长时间运行（30 分钟），周期性切换页面与滚动列表
- **操作**：每 1 分钟采样一次内存
- **测量**：内存增长趋势、泄漏检测、GC 频率

### 2.6 JS 执行性能
- **场景**：复杂业务逻辑计算、JSON 解析、大数据量处理
- **操作**：执行 1000 次取平均
- **测量**：单次执行耗时、JS 线程占用率

### 2.7 组件创建/销毁
- **场景**：批量创建 1000 个 View 组件，再批量销毁
- **操作**：重复 10 次
- **测量**：平均创建耗时、平均销毁耗时、内存回收效率

## 3. 测试工具与方法

### 3.1 内置性能监控
使用 `RNHPerfMonitor`（C++ 侧 + ArkTS 侧）实时采集：
- FPS（JS FPS + 原生 FPS）
- 内存（JS 堆 + 原生堆 + RSS）
- 启动时间线（T0/TI/TTI）

```typescript
import { RNHPerfMonitor } from '@rnoh-new/react-native-harmony';

const monitor = RNHPerfMonitor.getInstance();
monitor.startFpsMonitor();
monitor.startMemoryMonitor();

monitor.on('fps', (fps) => {
  console.log(`FPS: ${fps.toFixed(1)}`);
});

const stats = monitor.getPerfStats();
console.log(JSON.stringify(stats, null, 2));
```

### 3.2 鸿蒙系统工具
| 工具 | 用途 |
|------|------|
| `hdc shell` + `dumpsys meminfo` | 内存分析 |
| `hdc shell` + `top` | CPU 占用 |
| DevEco Studio Profiler | 性能剖析 |
| SmartPerf | 系统级性能分析 |

### 3.3 脚本化基准测试
使用 `scripts/perf-bench.js` 进行 Node.js 侧模拟测试：
```bash
node scripts/perf-bench.js
```
输出组件创建/更新/销毁的耗时对比表格。

### 3.4 测试方法
1. **预热**：每个场景测试前运行 30 秒预热
2. **多次采样**：每个指标至少采样 5 次，取平均值
3. **控制变量**：同一设备、同一系统版本、同一网络环境
4. **基线对比**：每次优化前后对比基线数据

## 5. 优化记录与成果

### v0.1.0（初始版本）
- **状态**：基线版本
- **列表滚动 FPS**：~45 FPS
- **启动时间**：~800 ms
- **初始内存**：~120 MB

### v0.2.0（组件层优化）
- **优化项**：
  - View 组件 props 批量更新，减少 C++ ↔ JS 通信次数
  - 引入 ShadowNode 复用机制
  - 优化布局引擎，减少 reflow 次数
- **预期收益**：
  - 列表滚动 FPS 提升至 55+
  - 组件创建耗时降低 30%

### v0.3.0（桥接层优化）
- **优化项**：
  - 批量事件上报，合并多次回调
  - JSI 直接调用，减少序列化开销
  - 内存池管理，减少 malloc/free 次数
- **预期收益**：
  - 启动时间降低至 500 ms 以内
  - 内存占用降低 20%

### v0.4.0（渲染层优化）
- **优化项**：
  - 引入 LRU 缓存复用 ArkUI 节点
  - 离屏渲染优化
  - 动画走原生线程，脱离 JS 线程
- **预期收益**：
  - 动画 FPS 稳定 60
  - 列表滚动稳定 58+
